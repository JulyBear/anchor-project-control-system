# ADR-001：采用“定锚”作为项目控制体系名称和架构方向

- 状态：提议，待人类决策者确认
- 日期：2026-09-12
- 决策范围：项目控制体系，不涉及产品技术选型

## 问题

项目由一个人和一个最强 AI 完成，需要防止跨会话遗忘、方向漂移、状态失真、需求与验证脱节，同时不能引入团队型流程的额外负担。

## 备选方案

1. 直接采用 BMAD、Spec Kit 或 AI-DLC 作为总控制器。
2. 把控制体系做成一个独立管理 Agent。
3. 采用项目原生控制层，并用 Skill 或脚本作为执行入口。

## 决策

暂采用方案 3，并命名为“定锚”（ANCHOR，Anchor Project Control System）。

控制权保留在项目文件和人类决策者手中；第三方框架只作为可替换执行机制，不能拥有唯一状态或最终批准权。

## 理由

- 项目只有一个人和 AI，不需要模拟多人组织；
- 项目文件比聊天记忆更适合作为长期、可审计、可恢复的事实来源；
- Skill 可以指导 AI 工作，但不能代替状态、证据和决策记录；
- 独立 Agent 会增加上下文和协调成本，暂不作为核心层；
- 先建立协议再做工具封装，可以避免把未经验证的流程固化。

## 后果

正面后果：控制权清晰、可迁移、不依赖单一框架、适合单人项目。

负面后果：初期需要维护少量项目文件；部分自动化能力要等协议稳定后再增加。

## 验证方式

通过沙盒实验验证：新会话恢复、状态冲突检测、中断恢复、需求变更影响分析、越界修改阻止、验证证据绑定和外部提示隔离。

## 重新评估条件

- 维护成本持续高于控制收益；
- 自动检查无法覆盖关键失控模式；
- 项目进入多人协作或需要外部需求工具交换；
- 明确出现独立审计 Agent 能显著提高安全性的场景。
